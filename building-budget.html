Build journal

Building the budget dashboard

One page, built from my own bank and card exports, that shows where the money goes. Most of the work was making sure it never shows a plausible wrong number.

2026 · five Python scripts and one HTML file · built by Claude, with Codex reviewing at each major step · private; there are no figures on this page, on purpose

A page that was wrong because someone typed it

The first version was a spreadsheet, then a dashboard whose summary sections were written by hand. That’s how, in August, it ended up showing an old figure and telling me to decide on options that had expired three weeks earlier. Nothing had crashed; the page loaded normally and gave no sign those sections were out of date.

So in August it was rebuilt as a program, with one rule at the top of the code: if a number appears, it was computed from the ledger. Five scripts read nine sources, apply categorising rules kept as data, and produce one self-contained page.

Seven bugs, none of them crashes

These seven bugs all produced believable output:

  • income swallowed by a rule that sat above the income rule;
  • an export that read zero rows because its dates had a time stuck on the end;
  • a transfer between my own accounts counted as spending;
  • a sort by filename that picked an older file, because “to 8 May” sorts after “to 7 Aug”;
  • a missing column that came back as zeros, which look exactly like real data;
  • amounts in two currencies added together;
  • cash counted as shares.

The checking script looks for errors that would leave the totals looking believable. If it fails, the page doesn’t get published.

A checker that agreed with itself

For months, refunds never reduced spending, and the check passed every time. It passed because it reused the same function as the thing it was checking, so it made the same mistake and agreed with it. The new check deliberately does the sum a different way. Run against the old method, it flags five affected months.

It disagreed, and it was right

In August Claude proposed upgrades: a monitor for drifting spending, a simulation of how long savings last, and a model of the risk of being forced to sell investments. Codex took them apart. The drift monitor would have cleanly caught none of the four real problems we’d found. The forced-sale model was, in its word, theatre. And it found something Claude had missed: no alert for a source that simply stops arriving.

A machine-learning categoriser went the same way. It would have scored about 97% while proving nothing, because it would be learning the rules it was being tested against. What got built instead: fixed rules, a few simple monitors and a calendar of what’s due. One example: a bill that moved from weekly to monthly billing looked like a price rise when compared charge by charge, even though the monthly cost fell. A rule that knows how often the bill comes reads that correctly.

Checking cancelled transactions

One card’s app marks cancelled transactions only with a strikethrough, which makes its screenshots harder to transcribe correctly. So each transcription gets checked against the app’s own monthly total, to the cent. Mr. B tried taking on the downloads and ran into too many limits. The method now is simple: I download every file myself, and Claude does everything after that.

Could a local model do it?

In November I tried small AI models running entirely on my own computer. My statements stood in for the kind of client data that should never go to a cloud model. Three of the four runs gave no answer at all. In two runs, adding the instruction that a transfer between my own accounts isn’t spending led to reasoning that went round in circles without an answer. The best run scored two out of five for usefulness. A second round is planned.

What AI did, and what it didn’t

Claude writes the code, reads the screenshots, runs each build and proposed every model, good and bad. Codex reviews the calculations and argues with proposed changes. My part: I download the files, identify the merchants it can’t place, make the classification and policy calls, approve new checks, and decide what the page is allowed to tell me.

Build journal

Building Layer

A checker for finished research decks. It grew out of a deck generator I stopped building after one comparison: with it, the review caught no more errors and took longer.

July–November 2026 · Python, runs on your own machine · built and reviewed by Claude and Codex, swapping roles · private alpha

Fifteen to twenty rounds per deck

The problem started with AI-made report decks. Each one took fifteen to twenty rounds before I could send it: bars showing the same percentage at different lengths on different slides, decimals that changed from chart to chart, charts nobody could edit. Writing the rules down didn’t help much, because the model would read a rule and then drift from it. By August I had 59 numbered deck rules. I wanted the rules enforced.

Deckforge

In September that became Deckforge: survey data in, a native, editable PowerPoint out, with the typography and chart rules enforced in code instead of in a prompt. It grew fast, to 619 tests and around 8,900 lines. By the end of September it felt endless. I couldn’t tell whether a working platform was days, weeks or months away, and when I asked, Codex withdrew its own estimates as unsupported. It was the right answer; I didn’t enjoy hearing it.

One comparison

On 27 October I ran the comparison I should have run earlier. Two fresh sessions got the same made-up survey packet with eight errors planted in it: one session had Deckforge, one didn’t. Both caught all eight, with no false alarms. Without Deckforge took 3 minutes 41 seconds. With it took 5 minutes 8 seconds.

In that one comparison, the generator showed no accuracy advantage, and the review with it took longer. The next day I changed direction: stop generating decks, and check finished ones instead. Researchers keep whatever tools they like for the thinking; the checker looks for the mechanical problems in the finished deck. It was briefly called Final Version, which I dropped because it sounds like a promise that the deck is cleared. Layer says what it checked and what it didn’t.

Show me the deck

Early versions reported their work the way software does: test counts, rule IDs, pass and fail. I turned that down as evidence: I wanted to see the changes on the slides as well as the test results. When the audit report still read as too technical, it was rebuilt to lead with what happened to the deck, with real before-and-after captures of the slides.

Close the gap now

Layer also had to keep track of each chart when slides moved, and at first it often lost them. Claude proposed fixing that later. I said no:

I’m worried about forgetting that these gaps exist … it’s not like I will remember to tell you when a new project exists … when we see gaps and we can close it, we close it.

The fix went in that night. Re-run on a controlled layout revision, every check found the object it belonged to after the slides moved; whether each one still means the same thing stays a person’s call.

The things a reviewer misses

Some of what Layer catches is invisible on the slide. The common Python library for making PowerPoint files leaves its own author’s name in the file properties, and dates from 2013. A file that leaves my hands should carry my name and nothing a library left behind, so Layer now checks and fixes file properties too. The independent reviewer had missed the same leftovers in Word files that Layer finds in seconds.

The engine releases since October have each been reviewed by the other provider; the newest piece, an installer, has passed its local checks and still waits for that review. One release came back NO GO with twelve findings, each fixed with a test that would catch it again. Another needed four rounds before it passed.

What AI did, and what it didn’t

All of the code and tests are AI-written. Codex built the first five alpha releases with Claude reviewing; Claude built the next four with Codex reviewing. The engine reached 210 tests, and the installer checks bring it to 215. My part: the change of direction, the name, the standards it checks against, the rule about file properties, the rule about closing gaps, refusing test counts as proof, supplying real decks to test it on, and being the last check.

What it can’t claim yet: there’s no measured time saving, and no proof it beats a careful human reviewer. Its first rule says a completed run never means the whole report is correct; a person still reviews the findings.
